# Ритм

Цели, задачи, привычки и календарь в одном приложении для iPhone (PWA). Своя система: ничего не подключается к Google Календарю и Apple Напоминаниям, все их функции реализованы внутри.

Что внутри:

- **Цели → подцели → задачи (с чек-листами).** Прогресс считается тремя способами на выбор для каждой цели: по доле задач, по весу задач или по числовой метрике («пробежать 150 км», «похудеть с 90 до 80 кг»).
- **Календарь:** день, неделя, месяц, год, список. События (с повторами и напоминаниями), задачи и привычки показываются вместе, есть фильтры. Задачи можно перетащить на таймлайн (долгое нажатие), блоки двигаются и растягиваются.
- **Привычки:** «да/нет», счётчик, таймер. Расписание: каждый день, по дням недели, N раз в неделю. Серии, процент выполнения, тепловая карта, привязка к целям.
- **Push-напоминания:** только для задач и событий. В уведомлении показываются название и время; отдельные переключатели позволяют отключить каждый тип.
- **Экран «Сегодня» с виджетами:** прогресс дня, ближайшее дело, привычки, расписание, задачи, цели, неделя, серия, просрочено. Включаются и переставляются в настройках.
- Светлая и тёмная тема, русский интерфейс, офлайн-режим, экспорт и импорт данных.

## Что важно знать про iPhone

PWA не может создавать виджеты на главном экране iPhone: это ограничение iOS для веб-приложений. Поэтому виджеты сделаны внутри приложения на экране «Сегодня». Push-уведомления на iPhone работают с iOS 16.4 и только если приложение добавлено на экран «Домой».

## Запуск за 5 минут (без синхронизации)

Приложение состоит из статических файлов. Нужен только HTTPS-хостинг.

**GitHub Pages**

1. Создайте репозиторий на GitHub и загрузите в него все файлы из этой папки.
2. Settings → Pages → Source: Deploy from a branch → `main` / `(root)`.
3. Через минуту сайт откроется по адресу `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/`.

**Netlify или Cloudflare Pages:** перетащите папку целиком, настройки сборки не нужны.

**Установка на iPhone**

1. Откройте адрес в **Safari**.
2. Нажмите «Поделиться» → «На экран “Домой”» → «Добавить».
3. Запустите «Ритм» с главного экрана.

В таком виде данные хранятся на этом телефоне и работают без интернета. Напоминания будут приходить, пока приложение открыто или работает в фоне. Для напоминаний при закрытом приложении и для синхронизации между устройствами нужен следующий раздел.

## Синхронизация и push при закрытом приложении

Нужен бесплатный проект [Supabase](https://supabase.com). Он хранит ваши данные и по расписанию отправляет push. Это ваш личный бэкенд, он не связан с Google и Apple.

1. **Проект.** Создайте проект на supabase.com. В Project Settings → API скопируйте `Project URL` и `anon public` ключ.
2. **База.** SQL Editor → вставьте содержимое `supabase/schema.sql` и выполните.
3. **Провайдеры входа.** Authentication → Sign In / Providers:
   - включите Email и отключите **Confirm email**, чтобы регистрация сразу создавала сессию без письма подтверждения;
   - включите Google и укажите OAuth Client ID и Client Secret из Google Cloud.
4. **URL авторизации.** Authentication → URL Configuration:
   - Site URL: `https://egor948.github.io/Ritm/`;
   - Redirect URLs: добавьте `https://egor948.github.io/Ritm/` и `https://egor948.github.io/Ritm/**`.
   - Для восстановления пароля Redirect URL должен вести на `https://egor948.github.io/Ritm/`, а не на корень `https://egor948.github.io/`.
   В Google Cloud в Authorized redirect URIs укажите callback Supabase: `https://buwdepheklyrrzofkinm.supabase.co/auth/v1/callback`.
5. **Ключи для push.** Выполните на компьютере (нужен Node.js): `npx web-push generate-vapid-keys`. Получите публичный и приватный ключи.
6. **Конфиг приложения.** Откройте `config.js` и впишите `SUPABASE_URL`, `SUPABASE_ANON_KEY` и публичный `VAPID_PUBLIC_KEY`. Загрузите обновлённые файлы на хостинг.
7. **Функция отправки.** Установите [Supabase CLI](https://supabase.com/docs/guides/cli), затем:
   ```
   supabase login
   supabase link --project-ref ВАШ_PROJECT_REF
   supabase secrets set VAPID_PUBLIC_KEY=... VAPID_PRIVATE_KEY=... VAPID_SUBJECT=mailto:ваш@email CRON_SECRET=придумайте_длинную_строку
   supabase functions deploy send-reminders --no-verify-jwt
   supabase functions deploy delete-account
   ```
8. **Запуск раз в минуту.** Database → Extensions → включите `pg_cron` и `pg_net`. Затем в SQL Editor выполните блок `cron.schedule(...)` из конца `schema.sql`, подставив свой `PROJECT_REF` и `CRON_SECRET`.
9. **Управление аккаунтом.** Личный кабинет в Настройках позволяет изменить имя, пароль и Email, запросить восстановление пароля и удалить аккаунт. Для удаления аккаунта предварительно задеплойте Edge Function командой выше. Секретный service role key хранится только в настройках Supabase и никогда не добавляется в клиентский код.
10. **В приложении.** Настройки → «Войти или создать аккаунт» → «Продолжить с Google» или вход по email. После возврата из Google Ritm автоматически завершит вход и синхронизирует данные. Для push нажмите «Включить напоминания». На втором устройстве войдите в тот же аккаунт.

Как работает синхронизация: локальные правки отправляются в облако примерно через 1–2 секунды. Supabase Realtime сообщает другим активным устройствам об изменении, после чего они автоматически забирают обновлённые записи и перерисовывают интерфейс без перезагрузки. Раз в минуту остаётся резервная проверка, а при возвращении в приложение и восстановлении сети выполняется дополнительная синхронизация. Для Realtime таблица `public.items` должна быть включена в публикацию `supabase_realtime`; блок для этого добавлен в `supabase/schema.sql`. Если одну запись изменили на двух устройствах, действует текущая логика выбора более свежей правки. Удаления синхронизируются тоже.

## Аккаунт и безопасность

- Смена Email выполняется через подтверждение писем Supabase.
- Восстановление пароля: «Забыли пароль?» на экране входа, затем переход по ссылке из письма и установка нового пароля.
- Удаление аккаунта удаляет пользователя Supabase; связанные строки `items`, `reminders` и `push_subscriptions` удаляются каскадно по внешним ключам.
- В Supabase → Authentication → Settings установите минимальную длину пароля не менее 8 символов.

## Резервная копия

Настройки → «Экспорт резервной копии» сохраняет JSON-файл. «Импорт из копии» восстанавливает данные.

## Структура

```

config.js                                  ключи Supabase и VAPID (по умолчанию пусто)

js/sync.js, push.js                        облако и уведомления
supabase/schema.sql                        таблицы и политики доступа
supabase/functions/send-reminders          отправка push
tests/logic.test.mjs                       тесты логики: TZ=Europe/Moscow node --test tests/logic.test.mjs
```

## Обновление приложения

Загрузите новые файлы на хостинг. В `sw.js` увеличьте `VERSION` (например, `ritm-v2`), чтобы телефон сбросил старый кэш.



### Несколько независимых напоминаний (4.6.0)

Для каждой задачи и каждого события можно добавить несколько напоминаний. У каждого напоминания своя дата и точное время; оно не зависит от даты или времени начала задачи/события. Напоминания синхронизируются вместе с записью и отправляются независимо. Старые напоминания задач при первом открытии и сохранении редактора переносятся в новый формат; старое напоминание события «перед началом» продолжает работать.

### Индикатор синхронизации (v4.4)
В настройках аккаунта отображается состояние синхронизации: отправка изменений, подключение Realtime, успешная синхронизация, отсутствие сети или ошибка. Realtime остаётся основным каналом доставки изменений, периодический REST pull — резервным механизмом.

### Push-уведомления (v4.5)
Поддерживаются только два типа: задачи и события. Заголовок уведомления — название записи, текст — её время (`Время: ЧЧ:ММ`; для события на весь день — `Весь день`). Для каждого типа есть отдельный переключатель в Настройках. Привычки и другие разделы push-уведомлений не создают.


### Очередь push-напоминаний (исправление 4.5.3)

Для уже подключённого Supabase один раз выполните в SQL Editor файл
`supabase/migrations/20261117_preserve_due_reminders.sql`.

Теперь при очередной синхронизации Ritm заменяет только будущие неотправленные напоминания.
Уже наступившие остаются в очереди, даже если другое устройство синхронизируется раньше минутного Cron.
Они отправляются при следующем запуске Cron; напоминания старше 6 часов сервер закрывает без отправки.


### Срок хранения push-уведомлений (4.5.4)

Сервер отправляет Web Push с `TTL: 86400` (24 часа). Если телефон временно не в сети,
push-провайдер может хранить уведомление до суток и попытаться доставить его после
восстановления соединения. Фактическая доставка зависит от push-провайдера и состояния устройства.
После изменения нужно повторно задеплоить Edge Function `send-reminders`.


### Интерфейс напоминаний и синхронизации (4.6.1)

Дата и время каждого напоминания обязательны. Карточки напоминаний получили отдельные поля и увеличенные отступы; статус синхронизации отображается отдельной строкой под адресом аккаунта.


### Сохранение позиции прокрутки при изменениях (4.6.2)

При добавлении и удалении пунктов чек-листа и напоминаний редактор сохраняет положение видимого элемента. То же восстановление применяется при обновлении списков задач и детальных экранов.


### Обновление списков без перерисовки редактора (4.6.3)

Добавление и удаление напоминаний и пунктов чек-листа изменяет только соответствующие элементы списка. Остальная форма остаётся в DOM, поэтому её позиция прокрутки не сбрасывается.


### Стабилизация прокрутки редакторов на iOS (4.6.5)

Положение прокручиваемой области шита фиксируется до нажатия кнопки и восстанавливается после завершения DOM-обновления и пересчёта Visual Viewport в Safari. Пользовательский жест прокрутки отменяет временную фиксацию.


### Исправление заголовков карточек напоминаний (4.6.6)

Убрана динамическая перенумерация заголовков карточек при добавлении и удалении. Заголовок каждой карточки остаётся одиночным «Напоминание».


### 4.6.7 — исправление заголовков напоминаний
- Заголовок каждой карточки формируется одним элементом: «Напоминание 1», «Напоминание 2» и т. д.
- Нумерация обновляется после добавления и удаления карточек; отдельная статичная надпись не дублируется.


### 4.6.8 — упрощение заголовка напоминаний
- Убрана нумерация карточек и иконка перед заголовком.
- В каждой карточке остаётся один заголовок «Напоминание», выровненный по левому краю по сетке полей даты и времени.
- Логика прокрутки редактора не менялась.


### 4.7.0 — выбор даты и времени без преждевременного закрытия
- Убрана полная перерисовка редактора при выборе даты и времени: она сбрасывала нативную панель выбора на iOS.
- В редакторе задачи поля времени и длительности обновляют видимость без пересоздания панели.
- При изменении времени начала события время окончания корректируется прямо в поле, без перерисовки редактора.
- Версия кэша Service Worker обновлена до ritm-v4.7.0.


### 4.7.1 — подтверждение выбора даты и времени
- Поля даты и времени открывают собственную панель Ritm с кнопками «Отмена» и «Готово».
- Выбранное значение хранится во временном черновике и применяется только после «Готово».
- Выбор значения в системном календаре/барабане больше не закрывает панель Ritm.
- Изменения применены ко всем полям даты и времени, включая задачи, события, привычки, цели и отдельные напоминания.
- Кэш Service Worker обновлён до ritm-v4.7.1.

 
### 4.7.2 — собственные выбор даты и времени; удаление длительности задач
- Системные поля date/time заменены календарём и колёсами выбора времени внутри панели Ritm. Выбор не закрывает панель; «Готово» применяет, «Отмена» отменяет.
- Календарь позволяет листать месяцы и менять выделенную дату без закрытия панели.
- Время выбирается отдельными прокручиваемыми колёсами часов и минут; выбранное значение видно до подтверждения.
- Поле «Длительность» удалено из редактора задач. Старое значение не влияет на планирование и очищается при сохранении или переносе задачи.
- В календаре задачи сохраняют фиксированный 30-минутный визуальный слот для размещения на временной сетке, но этот слот не является свойством задачи и не редактируется. Изменение длительности событий сохранено.
- Кэш Service Worker обновлён до ritm-v4.7.2.

 
### 4.7.3 — возврат системных календаря и времени; принудительное обновление интерфейса
- Удалены промежуточные панели Ritm для даты и времени. Поля снова используют нативные input type="date" и input type="time", которые сразу открывают системные элементы iOS.
- При изменении даты или времени редактор больше не перерисовывает поле и не пересоздаёт системный picker. Действия «Готово» и «Отмена» остаются штатными для iOS.
- В редакторе задач нет настройки длительности; старое значение очищается при сохранении, перенос задачи не добавляет его обратно.
- Растягивание блока задачи в календаре отключено; изменение длительности событий не затронуто.
- Service Worker cache обновлён до ritm-v4.7.3, предыдущий кэш удаляется при активации обновления.

 
### 4.7.4 — обновление PWA при запуске
- Регистрация Service Worker выполняет немедленную проверку новой версии при открытии приложения и игнорирует HTTP-кэш для скрипта обновления.
- Кэш оболочки обновлён до ritm-v4.7.4.
- Поля даты и времени используют нативные input type=date и input type=time без промежуточного экрана Ritm; обработчики редактора не вызывают redraw при выборе.
- Длительность задачи отсутствует в форме и в изменении размера блока календаря; растягивание по-прежнему доступно событиям.

 
### 4.7.5 — запрет новых напоминаний в прошлом
- В карточках независимых напоминаний минимальная дата — ближайшая доступная локальная дата; для сегодняшнего дня минимальное время — следующая минута.
- При выборе прошедшей даты или времени поле восстанавливает прежнее значение и показывает предупреждение.
- При добавлении напоминания начальная дата и время сразу выбираются в будущем.
- Проверка повторяется при сохранении редактора задачи и события. Уже существующие неизменённые прошедшие записи не мешают редактировать остальные поля.
- Добавлен тест проверки прошедших и будущих дат/времени.
- Кэш Service Worker обновлён до ritm-v4.7.5.

 
### 4.7.6 — запрет прошедших дат задач и событий; видимые уведомления
- В датах задачи и события установлен минимальный день — сегодня; попытка выбрать предыдущую дату отменяется с предупреждением.
- Повторная проверка выполняется при сохранении. Ранее созданные записи с уже прошедшей датой можно редактировать, если их дата не меняется.
- Уведомления приложения перенесены в фиксированную верхнюю область под системной строкой состояния, чтобы положение прокрутки редактора не влияло на их видимость.
- Длинный текст уведомления переносится на строки и не обрезается по ширине.
- Кэш Service Worker обновлён до ritm-v4.7.6.

 
### 4.7.7 — напоминания события и единый запрет прошедших дат
- Удалено старое поле напоминания перед началом события. При сохранении события legacy-поле reminderMin очищается; независимые напоминания остаются.
- Заголовок «Дополнительные напоминания» переименован в «Напоминания», раздел повтора теперь называется «Повтор».
- Явный выбор прошедшей даты блокируется даже если это та же прошедшая дата, которая была у редактируемой записи. Неизменённые старые даты не мешают редактировать другие поля.
- Быстрое создание задачи клавишей Enter проверяет выбранную дату и не создаёт задачу в прошлом.
- Перетаскивание задачи или мероприятия на прошедший день в календаре блокируется.
- Кэш Service Worker обновлён до ritm-v4.7.7.

 
### 4.7.8 — уведомления возвращены вниз экрана
- Все всплывающие уведомления снова появляются снизу, над нижней панелью и с учётом безопасной области устройства.
- Сохранены перенос длинного текста и ограничение ширины, поэтому предупреждения остаются полностью читаемыми.
- Анимация появления направлена снизу вверх.
- Кэш Service Worker обновлён до ritm-v4.7.8.

 
### 4.7.9 — надёжный выбор приоритета задачи
- Сегментированный выбор приоритета заменён на отдельные кнопки «Нет», «!», «!!», «!!!» с явным активным состоянием.
- Кнопка «Нет» всегда доступна и немедленно снимает приоритет без перерисовки редактора.

### 4.8.0 — перетаскивание виджетов
- В редакторе виджетов убраны кнопки перемещения вверх и вниз.

- При перемещении список автоматически прокручивается у верхней и нижней границ редактора.

### 4.8.1 — плавное перетаскивание виджетов
- Перетаскиваемая строка остаётся в DOM на исходном месте во время жеста; отдельная плавающая карточка следует за пальцем или мышью, поэтому захват указателя не теряется при перестановках.
- В списке отображается анимированное место вставки, которое может перемещаться через любое количество строк.
- Порядок в меню настроек и на экране «Сегодня» берётся из одного сохранённого массива и совпадает после отпускания.
- Добавлены плавные FLIP-анимации соседних строк, карточка-предпросмотр с мягкой тенью и автопрокрутка у краёв списка.
- Перетаскивание отключает автоматическое восстановление прокрутки шита на время жеста.
- Кэш Service Worker обновлён до ritm-v4.8.1.

### 4.8.2 — завершённая механика перетаскивания виджетов
- Карточка под пальцем отображается отдельным плавающим предпросмотром; исходный элемент остаётся в DOM и удерживает указатель на всём протяжении жеста.
- Место вставки перемещается независимо от исходной строки, поэтому один виджет можно перенести сразу через несколько позиций.
- В меню настроек порядок элементов меняется во время перетаскивания и сохраняется после отпускания; тот же порядок используется на экране «Сегодня».
- Соседние строки плавно разъезжаются и возвращаются на новые места; оформление предпросмотра использует полупрозрачную стеклянную карточку и мягкую тень.
- Автопрокрутка останавливается на границах списка; системное восстановление прокрутки листа не вмешивается в жест.
- Кэш Service Worker обновлён до ritm-v4.8.2.

### 4.10.0 — короткое исчезновение выполненных задач и отмена
- После отметки задача остаётся видимой примерно 2,2 секунды: название зачёркивается, карточка становится приглушённой.
